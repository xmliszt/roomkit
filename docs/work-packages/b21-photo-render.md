# B21 — Render a realistic photo of the current view with Blender Cycles (Codex agent)

Read `docs/work-packages/README.md` first. Spec: `docs/PLAN.md` (jobs, machine lock, Blender runtime, the "Lighting" entry in section 8: this is its phase 2, global illumination), `docs/DESIGN.md` (snapshot, jobs panel, chat media blocks, lighting paragraph). The user asked for this on 2026-11-24: a realistic photograph (效果图) of the current view, free and local. A22 (light sources) is still on its branch `wp/a22-light-sources`: build the export, render, job and UI first without lights, read A22's `LightSchema` (with `beam`: spot cone or all directions, `emitter` as 0–1 box fractions) from that branch, and add lights once A22 merges into `orchestrator` (merge `orchestrator` often). A beam renders as a Cycles spot light with the same cone; a shaded lamp's shade also blocks light physically in Cycles. If you need a new command, WS message, job kind or chat block shape, write the exact shape in your first commit's PLAN change and ask the orchestrator before building on it.

## Scope

1. **Trigger.** A "Render photo" action beside the snapshot button (and in the command palette), plus an MCP tool so the designer can render on request. It captures the current camera (position, target, field of view, aspect of the viewport) and starts a `render` job. The editor stays usable while it runs.
2. **Scene export (daemon).** Write a job folder with the room (walls with openings, floor, ceiling and their surface materials: paint colour and finish, wallpaper/tile/plank textures at their real scale), every visible item's GLB with its placement, size scaling, mirroring and `colorAdjust` applied (reuse `recolor.py` logic or bake), lights that are on (`emitter`, `lumens`, `temperatureK`), and the camera. Hidden or pending items are left out. Walls, ceiling and wall corners that the editor hides for the current camera (orbit view hides near walls and the ceiling from above) are invisible to camera rays but still block and bounce light, so an orbit render shows the open-sided room the user sees, lit as a closed room.
3. **Render (Blender, `blender/render_photo.py`).** Cycles on the Metal GPU (fall back to CPU), OpenImageDenoise, physically based light units (lumens to watts with one documented constant, colour from Kelvin), a soft daylight term through window openings if there are windows, AgX view transform, 1920 px on the long side by default, a sample count chosen so a typical room renders in about 2 minutes on the M1 Pro (measure and record). Runs under the machine lock. Report progress (samples done) so the job row shows a real percentage, and support cancel.
4. **Result.** A PNG in the project (`renders/<jobId>.png`), a chat media block with the image (downloadable, full size on click), and the job in Jobs with duration. Failure text in plain words (Blender missing, out of memory, cancelled).
5. **Docs:** PLAN (render job, export format, timings), DESIGN (button, job row, chat block).
